# 사이트 수정 실전 메뉴얼

## 0. 이 문서의 목적
이 문서는 `justini0715.github.io` 저장소를 **직접 수정할 때 필요한 실전 지식**을 한 문서에 모아 둔 메뉴얼이다.

대상 독자:
- 라우팅 구조만 이해하고 직접 페이지를 추가/수정하고 싶은 사람
- 나중에 오랜만에 다시 돌아와도 빠르게 구조를 파악하고 수정하고 싶은 사람
- 디자인보다 먼저 **어디를 건드려야 하는지** 정확히 알고 싶은 사람

이 문서를 다 읽고 나면 최소한 아래를 할 수 있어야 한다.
- 원하는 URL 위치에 새 페이지를 만든다
- 상단 네비게이션에 새 항목을 추가한다
- 프로젝트 / 블로그 / 42 글을 각각 올바른 위치에 추가한다
- 공통 UI와 전역 스타일이 어디서 관리되는지 안다
- `/studio`가 어떻게 동작하는지 이해한다
- 수정 후 무엇을 검증해야 하는지 안다

## 1. 이 사이트가 어떤 구조인지 한 번에 이해하기

이 저장소는 **Astro 기반 정적 사이트**다.
즉, 대부분의 페이지는 빌드 시 HTML로 생성되고 GitHub Pages에 배포된다.

핵심 디렉터리만 먼저 보면 된다.

```text
src/pages/           실제 라우트(페이지)
src/components/      공통 UI 컴포넌트
src/layouts/         공통 레이아웃
src/styles/          전역 스타일
src/content/         글/프로젝트 원본 Markdown 콘텐츠
src/lib/             헬퍼 함수와 콘텐츠/Studio 로직
public/              이미지, 파비콘, 정적 파일
docs/                설계 문서, 체크리스트, 런북
```

중요한 원칙:
- **`dist/`는 수정하지 않는다.** → 빌드 결과물이다.
- 실제 수정은 거의 항상 **`src/`, `public/`, `docs/`** 안에서 한다.
- URL 구조는 대부분 **파일 경로 그대로** 정해진다.

---

## 2. 라우팅 구조 이해하기

Astro는 기본적으로 **파일 시스템 라우팅**을 쓴다.
즉, `src/pages` 아래 파일 경로가 URL이 된다.

### 현재 공개 라우트 구조

| 파일 | URL | 역할 |
|---|---|---|
| `src/pages/index.astro` | `/` | showcase / gateway |
| `src/pages/home.astro` | `/home` | personal hub / now page |
| `src/pages/about.astro` | `/about` | profile / working style |
| `src/pages/projects/index.astro` | `/projects` | 프로젝트 인덱스 |
| `src/pages/projects/[slug].astro` | `/projects/[slug]` | 프로젝트 상세 케이스 |
| `src/pages/42/index.astro` | `/42` | 42 전용 허브 |
| `src/pages/42/[slug].astro` | `/42/[slug]` | 42 글 상세 |
| `src/pages/blog/index.astro` | `/blog` | 일반 기술 블로그 인덱스 |
| `src/pages/blog/[slug].astro` | `/blog/[slug]` | 일반 기술 글 상세 |
| `src/pages/studio.astro` | `/studio` | 로컬 전용 작성 도구 |
| `src/pages/404.astro` | `/404` | 404 페이지 |

### 새 페이지 추가 규칙

#### 1) 단일 페이지 추가
파일:
```text
src/pages/resume.astro
```
URL:
```text
/resume
```

#### 2) 폴더형 섹션 추가
파일:
```text
src/pages/archive/index.astro
```
URL:
```text
/archive
```

#### 3) 중첩 경로 추가
파일:
```text
src/pages/career/frontend.astro
```
URL:
```text
/career/frontend
```

#### 4) 동적 페이지 추가
파일:
```text
src/pages/notes/[slug].astro
```
URL 예시:
```text
/notes/my-first-note
```

### 반드시 기억할 것
- URL을 만들고 싶으면 **`src/pages`에 파일을 만든다**
- 섹션을 만들고 싶으면 **폴더 + `index.astro`**를 쓴다
- `[slug]`는 동적 라우트다

## 3. 페이지를 만들 때 기본적으로 쓰는 방식

대부분의 페이지는 아래 구조를 따른다.

```astro
---
import MainLayout from '../layouts/MainLayout.astro';
---

<MainLayout title="페이지 제목" description="페이지 설명">
  <section class="section">
    <div class="container">
      <h1>페이지 제목</h1>
      <p>내용</p>
    </div>
  </section>
</MainLayout>
```

### 언제 어떤 레이아웃을 쓰는가

- `LandingLayout`
  - `/` 같이 첫인상/게이트웨이 페이지
- `HubLayout`
  - `/home` 같이 허브형 페이지
- `ArchiveLayout`
  - `/projects`, `/blog`, `/42` 같이 인덱스/아카이브 페이지
- `ArticleLayout`
  - `/blog/[slug]`, `/42/[slug]`, `/projects/[slug]` 같이 읽기 중심 상세 페이지
- `MainLayout`
  - 특수 페이지나 단독 성격의 일반 페이지

즉, 새 페이지를 추가할 때는 먼저 이 질문을 하면 된다.

> “이 페이지는 게이트웨이인가, 허브인가, 아카이브인가, 상세 읽기 페이지인가?”

그에 맞는 레이아웃을 고르면 된다.

## 4. 상단 네비게이션 수정하기

상단 네비게이션 항목은 여기서 관리한다.

파일:
```text
src/data/site.ts
```

현재는 `siteMeta.nav` 배열이 source of truth다.

예시:
```ts
nav: [
  { href: '/home', label: 'Home' },
  { href: '/projects', label: 'Projects' },
  { href: '/42', label: '42' },
  { href: '/blog', label: 'Blog' },
  { href: '/about', label: 'About' }
]
```

### 새 메뉴를 넣고 싶으면
예를 들어 `/resume`를 만들고 메뉴에 넣고 싶다면:

```ts
{ href: '/resume', label: 'Resume' }
```

### 주의
- brand 클릭은 `/`로 이동한다
- `Studio`는 **production nav에 넣지 않는다**
- top-level nav에는 `Tags`, `Archive`, `Series` 같은 내부 탐색용 항목을 넣지 않는다
  - 이런 건 `/blog`나 `/42` 안의 secondary navigation으로 둔다

## 5. 콘텐츠 기반 페이지와 직접 만든 페이지의 차이

이 사이트에는 두 종류의 페이지가 있다.

### A. 직접 만든 페이지
- `src/pages/...`에 Astro 파일로 직접 작성
- 예: `/`, `/home`, `/about`, `/projects`

### B. 콘텐츠에서 자동 생성되는 페이지
- `src/content/...`의 Markdown/MDX를 읽어서 동적으로 생성
- 예: `/blog/[slug]`, `/42/[slug]`, `/projects/[slug]`

즉,
- **페이지 구조를 직접 만들고 싶다** → `src/pages`
- **글/프로젝트 데이터를 추가해서 자동 페이지를 만들고 싶다** → `src/content`

## 11. `/studio`는 일반 페이지와 다르게 생각해야 한다

### `/studio`의 역할
- 공개 CMS가 아님
- **로컬 전용 작성 도구**
- production에서는 잠금 notice만 보여준다

### 관련 파일
- 페이지 진입: `src/pages/studio.astro`
- 실제 UI: `src/components/WritingStudioApp.astro`
- 저장/파싱/템플릿 로직: `src/lib/studio/blogStudio.ts`

### 중요한 동작 규칙
- production: editor UI 노출 안 함
- dev(localhost): editor 활성화
- 일반 글 target: `src/content/blog`
- 42 글 target: `src/content/forty-two`
- `.md`, `.mdx` 로드 지원
- non-Chromium 브라우저는 다운로드 fallback

### 즉, `/studio`는 이렇게 생각하면 된다
- **public page가 아니라 local authoring tool**
- 고칠 때는 `pages`가 아니라 `WritingStudioApp.astro`와 `blogStudio.ts`를 봐야 한다

## 17. 절대 잊으면 안 되는 것

### 1) `dist/`는 수정하지 않는다
빌드 결과물이다. 다시 생성된다.

### 2) content 규칙을 어기면 빌드가 깨진다
- frontmatter 오타
- 잘못된 category
- 잘못된 date 형식
- schema에 없는 필드

### 3) `/studio`는 production 편집기가 아니다
배포본에서 editor UI가 안 보이는 게 정상이다.

### 4) 디자인만 건드려도 빌드는 확인한다
정적 사이트라도, CSS/컴포넌트 수정은 전체 페이지 레이아웃에 영향 준다.

### 5) 공통 구조를 모르겠으면 먼저 `pages → components → global.css` 순서로 본다
이 순서가 가장 빠르다.

## 18. 문제 생겼을 때 어디부터 볼지

### 페이지가 안 뜬다
- `src/pages/...` 파일명 확인
- 경로 오타 확인
- `npm run build` 에러 확인

### 글이 안 나온다
- `src/content/...` 위치 확인
- frontmatter 확인
- `src/content.config.ts` 확인

### 네비 메뉴가 안 바뀐다
- `src/data/site.ts` 확인
- `SiteHeader.astro`, `SiteFooter.astro` 확인

### 디자인이 이상하다
- `src/styles/global.css` 확인
- 공통 컴포넌트에 className이 맞게 붙었는지 확인

### Studio가 안 저장된다
- Chromium 계열 브라우저인지 확인
- localhost에서 열었는지 확인
- production `/studio`는 원래 잠금 화면인 점 확인
